# BCG参考模板可复用Layout合同

## 1. 来源与吸收边界

来源为用户提供的32页BCG管理者任命述职参考模板，分析日期为2026-07-16。只吸收页面的信息架构、证据组织方式和标题纵向节奏；不复制业务内容、绿色配色、Trebuchet／微软雅黑字体、顶部四段进度条、纹理、剪贴画、阴影、红色批注或低于10 pt的正文。

Mck仍是画布、0.8 in安全边距、动态栏距、正文容量、页脚和机读门禁的基础源。以下7种Layout是KSIB在Mck基础上的证据型增强，每页只能选择一种主Layout。

## 2. 已吸收的7种Layout

### 2.1 `evidenceInsight`｜主证据＋管理洞见

BCG来源页：P4、P7、P23、P24。

- 适用问题：一张核心图表、数据表或事实证据需要回答“这说明什么”。
- 几何：主证据区占内容宽度65%–75%；右侧或下方洞见区占25%–35%。
- 结构：事实标题 → 主证据 → 2–4条洞见／管理含义；洞见区承担本页Implication，不再另设Takeaway。
- 约束：不得再并列第二张同权图表；洞见必须解释证据，不复述数字；`evidenceInsight`属于Takeaway禁用Layout。
- Certified实现：正式采用右侧洞见时只使用`certified-layout-registry.json`中的`right-panel-standard`或`right-panel-subtitle`；主证据、洞见容器、标题、Lead和2–3条洞见分别绑定固定Slot。超过3条时先压缩未锁定内容、改用其他已批准Variant或拆页，不得缩字号和自由移动。
- 不适用：三个项目并列、纯文字清单、没有主证据的观点页。

### 2.2 `phasePlaybook`｜阶段打法表

BCG来源页：P8、P13。

- 适用问题：策略或能力按3–4个阶段递进，且各阶段需要同口径比较。
- 几何：横向阶段等宽；纵向共享3–4行，如核心逻辑、关键动作、成功标准、未解问题。
- 结构：阶段标题／时间 → 同构信息行 → 向右演进关系 → 可选唯一Takeaway。
- 约束：每个阶段不超过4个信息单元；不得在表格外再叠一条独立时间线。
- 不适用：阶段之间没有先后或因果关系的并列主题。

### 2.3 `problemSolutionMap`｜问题—原因—解法映射

BCG来源页：P15、P17。

- 适用问题：需要把3–5个业务／组织卡点逐一映射到解决动作和Owner机制。
- 几何：左侧问题35%–40%，中间因果／接口10%–15%，右侧解决方案45%–55%。
- 结构：问题／症状 → 原因或决策接口 → 对应解法／目标状态。
- 约束：必须逐行对应；不可把左侧问题清单与右侧方案清单无映射地并排。
- 不适用：只需展示Before／After的简单两列页。

### 2.4 `processModeMatrix`｜流程 × 运营模式

BCG来源页：P22。

- 适用问题：同一端到端流程存在2–3种运营／产品化模式，需要比较责任边界、效率和可扩展性。
- 几何：横向5–6个流程阶段；纵向2–3种模式；最右或最下放一个选择结论。
- 结构：流程阶段 → 模式覆盖范围／责任主体 → 差异证据 → 推荐模式。
- 约束：单元格只写责任或关键动作，不写段落；批注与风险进入Speaker Notes。
- 不适用：单一流程，无需比较多种模式时改用process_chevron。

### 2.5 `layeredOperatingModel`｜分层运营模型

BCG来源页：P26、P28。

- 适用问题：一项业务需要同时呈现主链路、横向能力、承接层和结果反馈。
- 几何：上层为业务链路／场景，中层为横向能力，下层为承接／数据／反馈；右侧可放目标状态，但不超过内容宽度30%。
- 结构：业务场景 → 横向赋能 → 结果承接／反馈；用对齐和细线表达跨层作用。
- 约束：层数最多3层、每层节点最多5个；不得做成复杂组织树或技术架构图。
- 不适用：只有单一路径或单一Owner的流程页。

### 2.6 `strategyEnablers`｜战略判断＋支撑能力

BCG来源页：P3、P27。

- 适用问题：Leading Page需要说明一个核心战略选择，以及使其成立的3–4项支撑能力／机制。
- 几何：核心判断／系统占55%–65%，支撑能力占35%–45%；支撑项使用同构短句。
- 结构：核心战略判断 → 3–4项Enabler → 结果／边界 → 可选唯一Takeaway。
- 约束：核心判断必须唯一；不得用装饰性图标、六边形或纹理模拟BCG原页。
- 不适用：需要展开详细执行路径或多阶段计划的页面。

### 2.7 `reflectionEvolution`｜过去—当前—目标

BCG来源页：P31。

- 适用问题：管理角色、组织成熟度或个人心态的三阶段演进。
- 几何：三阶段横向同构；当前用橙色描边，目标可用唯一浅橙Highlight Box。
- 结构：阶段定位 → 行为变化 → 时间／责任对象 → 可验证事实。
- 约束：每阶段使用相同信息层级；必须说明“为什么升级”，不可只写口号。
- 不适用：纯时间履历或项目里程碑，改用timeline。

## 3. 对现有Mck Layout的增强，而非新增

- `matrix_2x2`／portfolio：吸收BCG P29“横轴时间／纵轴预期价值”的清晰轴语义，但继续使用Mck矩阵合同，不新增第二套2×2。
- `twoColumn`／side_by_side：吸收BCG P16、P21左右两侧结论先行、证据随后展开的层级，但继续使用Mck动态栏距。
- `appendixProject`：吸收BCG P18–P20的截图证据组织方式，但只在证据页或附录使用，不把截图拼贴作为正式内容页默认风格。

## 4. 明确不吸收

- 顶部四段绿色／灰色进度条：与KSIB“III-X｜页面名称”页眉争夺空间，不设为全局默认。
- BCG标题颜色、Trebuchet／微软雅黑字体和约0.69 in窄边距：分别由KSIB配色、苹方-简和Mck 0.8 in安全边距覆盖。
- 纹理、阴影、剪贴画、EMF图标和红色审阅批注：不进入正式模板。
- 过长的两三行标题、低于10 pt的正文、多个底部结论框：由KSIB字号与单一Takeaway门禁拦截。
- 为视觉填满而增加模块：任何增强Layout仍遵守“一页一个核心判断、一个主视觉、至多一个Highlight Box”。
