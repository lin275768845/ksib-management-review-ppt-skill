# KSIB-MBB-FORMAT-6P-V1

本规范定义一套固定6页、只评估格式与原生编辑性的Golden Deck。它不评价研究内容、故事线或文案质量；所有文字和数字均为虚构测试数据。

## 1. 全局合同

| 项目 | 固定要求 |
|---|---|
| 画布 | 13.333 × 7.5 in，16:9，白底 |
| 安全边距 | 左右0.80 in；正文底部不超过6.85 in |
| 字体 | 所有主题和直接字体均为`PingFang SC`；粗细使用run级`b`属性 |
| 字号 | 封面44/24/16/14；内容标题22；正文16/14/12；附录正文10；来源与页码9 |
| 颜色 | `#FF4906`、`#D83D00`、`#FFF7F3`、`#FFDBCD`、`#1F2329`、`#646A73`、`#3B4048`、`#E5E6EB`、`#FFFFFF` |
| 风格 | 无渐变、阴影、3D、玻璃拟态或Emoji；通过对齐、细线和留白分组；表格默认白底表头、无外框与竖线 |
| Header | P2–P6统一页眉；页眉小矩形与页眉文字跨页0 EMU一致；Action Title固定为单行；内容页标题下不使用横向分隔线 |
| Footer | 分隔线位于`(0.80,6.95,11.733,0)`；Source位于`(0.80,7.05,10.80,0.20)`；页码位于`(12.20,7.10,1.00,0.30)`；三者跨页0 EMU一致 |
| 文本框 | Header、Title、Subtitle零内边距；禁止自动缩小字号；Title-only主体从1.52 in开始，Title＋Subtitle主体从1.66 in开始 |
| Takeaway | 6页全部禁用；标题已完整表达结论 |
| 图片 | 不需要图片；整页、图表、表格或流程栅格化均失败 |

普通单页对象相对设计Token的坐标容差为`±0.03 in`；固定Chrome的跨页比较使用`geometryToleranceEmu: 0`。对象角色、几何与原生类型以`../../references/golden-deck-format-contract.json`为机器真相源。

## 2. 六页固定页面

| 页码 | Layout | 必须存在的原生对象 | 核心交互 |
|---:|---|---|---|
| 1 | Cover | 5个文本框＋1条Accent Shape | 改字、改字体、撤销 |
| 2 | Single Exhibit | 1个原生Chart＋指标文本 | 编辑Chart数据、改单柱颜色、撤销 |
| 3 | Table Insight | 1个原生Table＋1个洞察区 | 改单元格、改单元格填充、取消加粗 |
| 4 | Two Column | 2个等宽多段落文本框 | 独立修改run颜色与加粗 |
| 5 | Value Chain | 4个节点＋4个原生Connector | 移动节点后连接器保持吸附 |
| 6 | Appendix Table | 1个高密度原生Table | 10pt正文可读、单元格可编辑 |

### P1 封面

- Title：`KSIB / MBB FORMAT\nGOLDEN DECK`；这是封面主标题，不属于内容页Action Title单行门禁。
- Subtitle：`咨询型PowerPoint格式与原生可编辑性基准`
- Statement：`固定6页、固定对象、固定样式；仅评估格式与编辑性，不评估内容生成`
- Meta：`Benchmark v1.0｜2026-07-30`
- 不显示Header、Source、页码或Takeaway。

### P2 原生图表

- Title：`类别D达到57，形成唯一视觉焦点；其余三项保持中性呈现`
- Subtitle：`基准测试虚构数据｜单系列、4个类别、单位：指数`
- 数据：A=18、B=32、C=41、D=57；使用横向条形图，D使用橙色，其余中性灰。
- 数值直接标注在条形末端；删除数值轴、网格线与图例，避免重复编码。
- `chart-main`必须是原生Chart。当前基准构建器生成`nativeLiteral`；正式客户Deck如要求PowerPoint“编辑数据”维护，合同应升级为`embedded-workbook-required`。

### P3 原生表格

- Title：`原生表格应在高信息密度下保留单元格级格式控制`
- `table-main`必须是原生`a:tbl`。
- 表头为白底深色字，不显示外框与竖线；数字列右对齐，仅保留表头和合计规则线。
- D行`+26%`为橙色粗体；合计行为白底粗体并使用橙色上规则线。
- `insight-panel`使用橙色竖向细线分组，不使用卡片式Highlight Box，也不是Takeaway。

### P4 左右比较

- Title：`左右比较依靠统一基线、等宽列和局部强调建立清晰取舍`
- 左右列分别位于`(0.80,1.60,5.69,4.90)`与`(6.84,1.60,5.69,4.90)`。
- 每列使用一个原生多段落文本框；标签和数字使用run级局部样式。
- 不使用卡片墙、Subtitle或Takeaway。

### P5 流程与连接器

- Title：`四个原生节点串联端到端流程，复核反馈闭环返回输入端`
- 四个节点依次为接收输入、选择版式、生成页面、校验交付。
- `connector-1/2/3`及`feedback-connector`必须是`p:cxnSp`，同时具有起终节点连接关系与箭头端点。

### P6 高密度附录

- Title：`高密度附录可以使用10pt正文，但不能牺牲可读性和编辑性`
- `appendix-table`必须是原生`a:tbl`，列出基准对象、字号、样式、交互动作和预期结果。
- 表头使用浅灰底深色字，不显示外框和竖线；当前8行表仅保留极浅横向规则线，不启用斑马纹。
- 不得因高密度把正文缩至10pt以下。

## 3. 阻断门禁

以下任一项发生即`blocked`：

1. PowerPoint出现修复提示、宏或未批准外部关系；
2. 页数、页序或画布尺寸不符；
3. P2不是原生Chart、P3/P6不是原生Table、P5不是原生且吸附的Connector；
4. 页面或主要证据被栅格化；
5. 普通用户对象存在编辑锁；
6. 规定的文字、颜色、加粗、单元格、图表数据或连接器交互不能完成；
7. 文字、数字、页序、颜色、字号或加粗语义发生漂移；
8. 使用未批准字体，正文或附录字号低于下限；
9. Action Title、Subtitle、Takeaway重复或无意义地叠加；
10. 同一Chrome Profile内的固定角色存在1 EMU几何差异或受控样式差异。
11. 内容页Action Title包含多个段落、显式换行、超出单行容量或最终PNG出现软换行。
12. 默认正文出现`title-divider`，或主体锚点高于对应Header模式的1.52／1.66 in起点。
