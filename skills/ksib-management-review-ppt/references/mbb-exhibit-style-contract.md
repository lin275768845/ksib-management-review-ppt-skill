# MBB 图表与表格样式合同

本合同约束咨询型客户 Deck 中的数据图表与表格。目标不是模仿某一家咨询公司的品牌皮肤，而是复用 MBB 常见的信息层级：先让结论、比较关系和异常值被看见，再让读者读取完整数据。

## 1. 总原则

1. 图表和表格必须回答一个明确的 `proofQuestion`，不能只是把数据搬到页面。
2. 默认白底、无阴影、无渐变、无三维；颜色只编码语义，不负责装饰。
3. 页面只保留一个主视觉焦点。KSIB 橙色默认只标记一个结论性系列、数据点、单元格或总计。
4. 图例、坐标轴、网格线、边框和表头底色都属于可删除的“图表墨水”；只有帮助理解时才保留。
5. 不把“深色表头”当作咨询风。黑色或深灰实心表头只能用于极高密度附录、法律／合规矩阵或客户既有模板明确要求的场景。

## 2. 表格默认样式

默认样式名为 `minimal-rule`：

- 表头无填充，使用深色粗体文字；
- 不显示外框和竖向分隔线；
- KSIB皮肤可在表顶保留一条`2 pt`橙色品牌规则线；它只负责页面识别，不视为数据重点；
- 表头下方保留一条 `0.75–1.0 pt` 中性灰规则线；
- 正文默认不显示单元格边框；行数较多、需要横向扫读时，可使用 `0.25–0.5 pt` 极浅灰横向分隔线；
- 首列和说明列左对齐，数字列右对齐；数字列的表头也右对齐；
- 单位放入列名或表格副标题，不在每个单元格重复；
- 百分比、小数位、货币和负号格式在同一列保持一致；
- 总计／小计行使用粗体和上规则线，不默认整行深色填充；KSIB主表允许使用`1.5 pt`橙色上规则线，但不得再叠加整行橙底；
- 重点单元格优先使用橙色文字或 `paleOrange` 浅底，禁止同时使用高饱和填充、白字和粗边框；
- 斑马纹只在超过 10 行、确实需要横向追踪时使用，且填充不深于 3%–5% 中性灰；
- 行高优先通过留白控制，不通过粗边框制造结构。

### 允许的表格变体

| 样式 | 适用场景 | 表头 | 正文线条 | 强调 |
|---|---|---|---|---|
| `minimal-rule` | 客户正文默认 | 白底深字，下规则线 | 无，或极浅横线 | 单点橙色 |
| `comparison-band` | 方案／品牌横向比较 | 白底深字 | 仅组间横线 | 推荐列浅橙底 |
| `heatmap-light` | 多指标优劣矩阵 | 白底深字 | 无竖线 | 低饱和单元格热度 |
| `appendix-dense` | 10pt高密度附录 | 浅灰底或白底 | 极浅横线 | 总计上规则线 |
| `client-template` | 客户模板强约束 | 继承模板 | 继承模板 | 不擅自改色 |

`dark-header`不是默认变体；如使用，必须在页面合同中填写 `styleExceptionReason`。

## 3. 图表默认样式

默认样式名为 `direct-label-spotlight`：

- 图表区域与绘图区无边框、透明或白底；
- 单系列图不显示图例；多系列能直接标注时也优先删除图例；
- 分类比较优先按业务顺序或数值降序排列；
- 重点系列／数据点使用 KSIB 橙色，其余使用一至两级中性灰；
- 数据标签直接贴近数据点，避免读者在图例、坐标轴和图形之间来回查找；
- 数值轴可被数据标签完全替代时隐藏；必须保留时只显示 3–5 个主刻度；
- 网格线默认删除；趋势或规模比较确实需要时，只保留浅灰主网格线；
- 不在图表内部重复页面 Action Title；图表小标题只写指标、单位、时期或口径；
- 不使用饼图展示超过 4 个分项，不使用 3D、阴影、渐变、外发光或彩虹色；
- “其他”默认置于末位并使用中性灰，不作为视觉焦点；
- 差异、CAGR、总计和异常值使用直接标注、括号、箭头或参考线表达，不另加机械式 Takeaway 框。

### 优先组件

| 证明任务 | 默认组件 | 关键格式 |
|---|---|---|
| 类别高低 | 横向条形图 | 降序、直接标值、弱化数值轴 |
| 时间趋势 | 折线图 | 线尾直接标注、减少圆点、弱化网格 |
| 结构占比 | 100%堆积条形图 | 直接标注主要分项，“其他”置末 |
| 增减桥接 | 瀑布图 | 总计／小计明确、正负语义一致、连接线克制 |
| 市场×份额 | Mekko／矩形面积图 | 宽度和高度分别绑定清晰维度，避免小格噪声 |
| 双变量优先级 | 散点／气泡图 | 直接标注重点点位，气泡大小写明口径 |
| 进度计划 | Gantt | 时间轴、活动条、里程碑和 Owner 对齐 |

## 4. think-cell 式能力的拆分

不要把 think-cell 理解成一种“黑表头＋灰色柱子”的皮肤。它真正值得复用的是：

1. 数据与图形持续绑定；
2. Waterfall、Mekko、Gantt 等管理图表组件；
3. 自动标签避让；
4. CAGR、差异箭头、总计／小计、轴截断等计算型标注；
5. 图表与数据表对齐；
6. 数据更新后仍维持版式和语义。

KSIB 的实现优先级应为：

`原生对象和数据绑定 → 直接标注 → 自动布局与避让 → 高级图表类型 → 视觉皮肤`

任何组件如果只能生成好看的 SVG／PNG，而不能保留客户所需的 PowerPoint 编辑能力，必须在 Release Manifest 中标为 `visual-fallback`，不得冒充原生 Chart 或 Table。

## 5. 交付检查

- 表头是否可以改为白底而不损失层级；
- 是否存在无意义的外框、竖线或全单元格网格；
- 数字列是否右对齐，格式和小数位是否一致；
- 总计、重点和异常值是否只使用一种主要强调手段；
- 图表是否仍有可删除的图例、轴、网格或内部标题；
- 强调色是否只指向页面的核心证据；
- 数据标签是否直接、无重叠，并在 PowerPoint 中可编辑；
- Chart／Table 是否保持原生对象，或已明确登记降级原因。
